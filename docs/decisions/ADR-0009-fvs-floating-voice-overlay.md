# ADR-0009: FVS 主画布悬浮语音层

## Status

Accepted

## Date

2026-06-10

## Context

V0.6 已切换为“数字人前端作为主页面, iframe 嵌入 FVS 看板”。用户进一步要求 FVS 成为页面主体: 未唤醒时页面角落只保留一个语音交互入口; 唤醒或连续对话时, 语音状态动画和文字记录悬浮在 FVS 上层。

语音链路还存在 Dora / RAGFlow / TTS 的等待时间。为了让现场体验更自然, 唤醒后的正式指令和连续追问进入处理时, 前端需要立即播放“收到, 正在查找信息”一类等待提示音。如果等待提示音播放中 AI 结果音频已生成, 应优先播放 AI 结果, 并打断等待提示音。

## Decision

- FVS iframe host 模式下, 前端使用全屏 FVS 作为主画布。
- 未进入唤醒 / 录音 / 思考 / 播报状态时, 右下角只显示一个麦克风圆形按钮。
- 语音唤醒、正式录音、连续追问、思考、TTS 加载或播报时, 右下角展开为悬浮语音面板。
- 主画布模式下的悬浮面板只展示语音监听状态、波形动画和对话文字记录; 调试表单、Mock ASR 输入和 Demo 按钮只保留在非 FVS 主画布模式。
- 正式指令或连续追问进入处理后, 前端立即播放固定等待提示语音。优先使用预生成的后端 TTS 音频; 如音频尚未就绪, 使用浏览器 `speechSynthesis` 做本地兜底, 并后台预热后端 TTS。
- AI 结果 TTS 与等待提示共用同一个播放通道。AI 结果开始播放前会清理当前等待提示音或本地合成语音, 保证结果音频优先。

## Consequences

- FVS 页面成为第一视觉层, 数字人交互不会抢占大屏主体。
- 麦克风权限仍由本项目主页面申请, 不再受 FVS 网页框权限策略限制。
- 等待阶段有即时声音反馈, 但仍可能受到浏览器自动播放策略影响; 保留文字状态和后续 AI 音频播放兜底。
- 非 FVS 主画布模式继续保留文本输入、Mock ASR 和 Demo 按钮, 方便本地调试。

## Guardrails

- FVS 控制仍必须走 `action_id` + Gateway 白名单校验。
- 不执行 Dora 或模型生成的 JavaScript。
- 不把 ASR / TTS / Dora API Key 放入前端。
- FVS、ASR、TTS、Dora 的 Mock 回退继续保留。
