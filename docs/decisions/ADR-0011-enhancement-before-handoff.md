# ADR-0011: 先功能增强再交付优化

## Status

Accepted

## Date

2026-06-10

## Context

V0.7 已补齐本地脱敏 Excel 问数链路, 具备稳定 POC 演示基础。用户进一步明确: 在输出验收报告、部署方案、用户手册等交付材料前, 先完成一轮功能增强, 包括 Dora 通用问数、TTS 字节级真流式、运维监控 / 日志看板、客户私有配置目录和更彻底的配置解耦。

如果现在直接进入交付文档, 很可能把尚未实现的功能边界写死, 后续返工成本更高。

## Decision

- 将 V0.7 之后路线拆为 V0.8、V0.9、V1.0。
- V0.8 聚焦功能增强:
  - Dora 通用问数 + Excel fallback。
  - TTS 字节级真流式 + 分段 TTS fallback。
  - 运维监控和日志看板。
  - 客户私有配置目录。
- V0.9 聚焦交付前优化:
  - 预检脚本。
  - 一键启停。
  - 日志导出。
  - 演示模式。
  - 异常体验优化。
- V1.0 聚焦正式交付材料:
  - 验收报告。
  - 部署方案。
  - 用户手册。
  - 运维手册。
  - 配置手册。
  - 测试报告。

## Consequences

- 新对话可以用 goal 的方式逐段实施, 不会把交付文档和功能增强混在一起。
- 功能增强仍必须遵守现有安全边界: `action_id` 白名单、不执行模型生成代码、不暴露 API Key、保留 Mock / fallback。
- 正式验收报告延后到 V1.0 输出, 以真实实现和验证结果为准。

## Guardrails

- 问数可以由 Dora 承接, 但必须保留 `excel` 模式和固定 Excel fallback。
- TTS 真流式必须保留当前分段 TTS 文件播放 fallback。
- 客户私有配置只能放非敏感 YAML; API Key 仍只进入本地 `.env` 或客户私有部署环境。
- 运维看板不得展示 API Key、完整密钥、供应商敏感响应或未脱敏客户数据。
