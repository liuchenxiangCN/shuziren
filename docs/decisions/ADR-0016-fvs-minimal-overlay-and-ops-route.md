# ADR-0016: FVS 极简悬浮层与独立运维路径

## Status

Accepted

## Date

2026-06-11

## Context

V0.6 的 FVS 主画布悬浮语音层实现后, 默认态的圆形麦克风入口偏大且视觉吸引力过强; 唤醒词未命中时也可能因 `wake_checking` / ASR 状态展开对话面板。展开态面板使用高不透明白色背景, 且包含监听状态、来源、动作和音频控件等信息, 会遮挡较大面积的大屏看板。

V0.8 为排障在同页增加了运维看板, 并在 FVS iframe host 模式下提供右上角“运维”悬浮入口。现场展示时, 大屏悬浮层应尽量只服务语音对话, 运维入口不应出现在客户可见的大屏画布上。

用户还要求唤醒成功时立即有语音反馈, 避免只有页面状态变化。

## Decision

- FVS iframe host 默认态只保留右下角小型低透明麦克风 icon, 不做常驻脉冲动画。
- FVS host 下仅在正式录音、连续追问、思考、TTS 加载或播报状态展开悬浮层; `monitoring`、`wake_checking`、`cooldown` 和未命中唤醒词不展开。
- FVS host 展开态改为半透明评论流, 只展示最近用户识别文本和数字人回复文本; 不展示来源、`action_id`、音频控件、监听调试信息或运维入口。
- 运维看板复用现有前端和 Ops API, 通过 `/ops` 独立路径访问; 不新增端口和后端接口。
- 命中唤醒词后立即播报固定提示 `您好。`; 若唤醒句中包含指令, 指令处理不等待该提示播完, 但等待提示 `收到, 正在为您查找信息。` 排在 `您好。` 后播放。
- 短提示优先使用预热的后端 TTS 音频; 未预热完成时使用浏览器 `speechSynthesis` 兜底。AI 最终回复音频仍可打断短提示。

## Consequences

- FVS 看板成为更纯粹的第一视觉层, 未启动时不会被语音入口明显抢注意力。
- 唤醒未命中的环境音不会造成对话浮层闪现。
- 运维能力保留, 但需要实施人员直接访问 `/ops` 或在非 FVS 主画布模式使用顶部切换。
- `/ops` 仍沿用本地 POC 内网使用前提和只读脱敏 Ops API; 是否增加鉴权仍作为正式交付前待确认事项。

## Guardrails

- FVS 控制仍必须走 `action_id` + Gateway 白名单校验。
- 不执行 Dora 或模型生成的 JavaScript。
- 不把 Dora / ASR / TTS / FVS API Key 放入前端或运维页面。
- Dora、ASR、TTS、FVS 的 Mock 回退继续保留。
