# 项目简介

## 背景

本项目定位为通用可配置数字人 POC 模板, 面向大屏、展厅、运营驾驶舱、知识问答和指标问数等场景。核心代码保持客户无关, 通过客户配置切换项目名称、客户名称、助手名称、唤醒词、Dora Agent、知识库、问数数据源、FVS 看板地址、控屏动作白名单、演示问题和话术。

中天证券党建大屏不再是项目本体, 而是当前仓库内的首个客户实例。该实例通过 `config/customers/zt-securities/`、`docs/customers/zt-securities/` 和交付包配置实现。

## 建设目标

本阶段目标不是一次性完成生产级交付, 而是先跑通完整链路:

```text
语音唤醒
-> 语音识别 ASR
-> 文本问题
-> Dora Agent
-> Dora 问数 / RAGFlow 知识库 / 大屏控制动作
-> 回复文本 / 图文结果 / screen_action
-> TTS 语音合成
-> 前端播报 + 动效 + 字幕 + FVS 控制
```

## 核心场景

- 客户欢迎语和角色化接待。
- 行业 / 客户知识库问答。
- 指标问数与总结分析。
- 语音控制大屏切换。
- 语音播报、字幕、状态动效和运维日志。

中天证券实例将这些通用能力配置为党建资料问答、党建指标问数、领导欢迎和 FVS 党建大屏切换。

## 本阶段非目标

- 不做 2D / 3D 数字人形象。
- 不做声纹识别。
- 不做人脸识别。
- 不做系统级常驻唤醒。
- 不做 FVS 看板重新开发。
- 不做真实生产知识库调优。
- 不做证券客户正式合规评审。
- 不承诺复杂问数和归因分析效果。
- 不让大模型直接生成并执行任意 JavaScript。
- 不把本地开发方案直接作为最终生产部署方案。

## 客户欢迎与身份匹配边界

本项目中的“身份匹配”不是严格身份认证, 只做文本层面的信息匹配。具体姓名、职务、欢迎语和资料库都应来自客户配置或客户知识库:

```text
用户自报姓名 / 职务 / 角色
-> 系统识别文本中的姓名、职务或角色
-> 在客户资料库中匹配
-> 若唯一命中, 生成欢迎语或相关新闻摘要
-> 若同名、同姓、同职务, 进行多轮确认
```

## 可复用目标

本工程的主线目标是客户无关的通用 POC 模板:

- 核心代码通用。
- 客户配置可替换, 中天证券只是一个配置实例。
- Dora Prompt 可替换。
- 大屏动作白名单可替换。
- 知识库样例可替换。
- 演示脚本可替换。
- 前端展示标题、客户名称、助手名称和场景名称可配置。
