# 项目简介

## 产品定位

本项目的目标产品是面向已经合法采购 FineReport、并使用 FVS 建设大屏客户的本地化“多大屏对话数字人管理平台”。

产品不重做客户已有报表和大屏，而是在既有 FineReport / FVS 资产之上增加:

- 单站点、多大屏的统一注册、配置、发布和运维；Site 层级保留未来扩展能力。
- 可复用、可版本化的数字人渲染扩展接口；首批只预留 2D / 3D Renderer / AvatarPackage 契约，不承诺具体资产格式。
- 可按大屏独立启停和组合的 Dora、LLM、知识库、ASR、TTS、问数与控屏能力。
- FineReport 官方智能问数插件、受控只读数据库和 Excel 三类问数 Provider。
- 从现有 `/ops` 演进而来的后台管理平台、RBAC、审计、监控、备份和升级能力。

详细目标设计见 [17_STANDARD_PRODUCT_DESIGN.md](17_STANDARD_PRODUCT_DESIGN.md)。

产品适配目标为 FineReport / FVS 11.0 大版本及之后版本，实际支持状态以精确版本组合兼容矩阵为准。

## 当前基线

当前代码仍是已经完成 V1.0 POC 验收包的单客户配置 / 单运行实例基线，并未实现上述标准产品目标。现有完整链路为:

```text
语音唤醒
-> ASR
-> 文本问题
-> Dora / 本地问数 / KnowledgeDirect / 控屏解析
-> 回复文本 / 图文结果 / screen_action
-> TTS
-> 前端播报 + 字幕 + 动效 + FVS 控制
```

现有客户方案和演示录屏场景只是配置实例，不是未来产品核心代码中的固定场景。

## 核心客户场景

- 展厅和经营驾驶舱的数字人接待与讲解。
- 围绕 FineReport / FVS 模板和业务指标的自然语言问数。
- 客户知识库问答与来源约束回答。
- 通过受控 `action_id` 切换 FVS 页面或执行白名单动作。
- 多块大屏使用不同形象、音色、能力和业务配置，同时统一运维。
- 实施人员通过向导完成大屏注册、预览、灰度发布和回滚。

## 产品化阶段目标

Productization P0 已完成以下产品边界设计:

- 目标客户、产品边界和部署边界冻结。
- 多大屏领域模型与配置发布模型。
- 2D / 3D Renderer / AvatarPackage 扩展接口和未来热插拔安全边界。
- 能力 Provider 与 FineReport 官方插件连接器边界。
- 后台管理平台信息架构、交付流程和验收矩阵。

当前进入 P1 领域、数据和控制面 API 契约设计，仍不实现新的运行时 API、数据库问数、官方插件调用、2D / 3D 渲染器或管理后台页面。

## 长期安全边界

- 不替代 FineReport / FVS，不做任意网页或任意 BI 的通用数字人 SaaS。
- 不让模型或普通用户生成并执行自由 SQL、Python、JavaScript 或 shell。
- 控屏只使用 `action_id`，并由后端完成白名单和参数 schema 校验。
- 2D / 3D 形象包不能携带任意可执行脚本；新渲染引擎属于受审计的产品升级。
- API Key、Token、密码和数据库 DSN 不进入前端或普通配置正文。
- FineReport 官方插件问数必须继承或收窄客户原有权限，权限拒绝不得通过备用 Provider 绕过。
- 客户化内容进入客户解决方案配置和客户文档，不硬编码进核心代码。

## 产品非目标

- 不做人脸识别、声纹认证或无感身份认证。
- 不承诺重建客户 FVS 大屏、FineReport 模板或数据仓库。
- 不在产品 V1 建设跨客户共享数据的公有云多租户平台。
- 不在未经参考环境压测前承诺固定并发数和硬件容量。
- 不把“大屏数和会话数无产品硬上限”表述成无限吞吐或高并发性能承诺。
- 不在未取得官方契约前承诺 FineReport 插件接口；插件由客户合法安装，产品始终不再分发。

## 可复用目标

- 同一客户标准部署管理一个站点内的多块大屏；Site 对象保留未来扩展能力。
- 数字人人设、形象、音色、能力套餐、连接、数据源和动作包可以跨屏复用。
- 每块大屏绑定明确版本，支持预览、灰度、发布和回滚。
- Dora、知识库、LLM、ASR、TTS 与问数 Provider 均可替换或关闭。
- Mock Dora / ASR / TTS / FVS 保留为开发、预览和故障演练能力。
- 客户解决方案不 fork 核心产品代码。
