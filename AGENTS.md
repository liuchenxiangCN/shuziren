# AGENTS.md

## Role

This repository uses documentation-driven development to build a reusable local POC for a party-building big-screen conversational digital human.

## Read First

Before any development, read:

1. `docs/CODEX_CONTEXT.md`
2. `docs/NEXT_ACTIONS.md`
3. `docs/DEV_LOG.md`
4. `docs/05_DEVELOPMENT_PLAN.md`
5. `docs/13_RISKS_AND_TODO.md`

If the task touches APIs or shared data structures, also read:

- `docs/06_API_CONTRACT.md`
- `docs/07_DATA_CONTRACT.md`

If the task touches external systems, also read:

- `docs/integrations/`

If the task touches customer delivery, also read:

- `docs/customers/zt-securities/`
- `docs/12_CUSTOMER_HANDOFF.md`

## Development Rules

- Only advance the current phase defined in `docs/NEXT_ACTIONS.md`.
- Do not jump ahead to real Dora, ASR, TTS, RAGFlow, or FVS integrations unless the current phase explicitly requires it.
- Keep Mock switches for Dora, ASR, TTS, and FVS.
- Do not expose API keys in frontend code.
- Screen control must use `action_id` plus backend whitelist validation.
- Never execute JavaScript generated by a model.
- Keep customer-specific content in customer config and customer docs, not hard-coded in core code.

## Documentation Rules

After each development round, update:

- `docs/DEV_LOG.md`
- `docs/NEXT_ACTIONS.md`
- `docs/CHANGELOG.md`

If risks, limits, or blockers change, update:

- `docs/13_RISKS_AND_TODO.md`

If architecture or technical decisions change, add or update:

- `docs/decisions/`

If APIs or shared data structures change, update:

- `docs/06_API_CONTRACT.md`
- `docs/07_DATA_CONTRACT.md`

## Completion Checklist

Before finalizing a task, confirm:

- Current task acceptance criteria are met.
- Tests or manual verification are recorded.
- Related docs are synchronized.
- The next task is written in `docs/NEXT_ACTIONS.md`.
